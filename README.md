# CyberTeacher

**CLI-приложение для обучения кибербезопасности с встроенным LLM-учителем**

---

## 🎯 О проекте

CyberTeacher — это интерактивный CLI-тренажёр для изучения кибербезопасности. У вас есть персональный AI-учитель (хакер из 90-х), который проводит вас через теорию, практику, CTF-задачи и реальные сценарии атак.

### Технологии
- **LLM провайдеры**: Ollama (локально) / OpenRouter / HuggingFace
- **Модели**: qwen2.5:7b, mistral, llama2 и другие
- **RAG**: ChromaDB + sentence-transformers + cross-encoder реранкинг
- **Интерфейс**: Rich (красивый CLI)
- **Практика**: Docker-лаборатории (DVWA, Juice Shop, Metasploitable и др.)
- **База знаний**: PDF-файлы, автоматическая индексация

## 🚀 Быстрый старт

```bash
# Клонировать репозиторий
git clone https://github.com/yourusername/CyberTeacher.git
cd CyberTeacher

# Установить зависимости
pip install -r requirements.txt

# Скачать модель Ollama (если используете локально)
ollama pull qwen2.5:7b

# Запустить
python main.py
```

## ✨ Новые возможности (2026-03-17)

### C-02: Социальная инженерия (`/social`)
Интерактивный диалоговый тренажёр, где вы — атакующий, а LLM играет жертву.

**Сценарии:**
- **Фишинг** — убедить перейти по ссылке и ввести пароль
- **Претекстинг** — получить пароль под видом IT-поддержки
- **Тейлгейтинг** — проникнуть в офис, Following someone

После диалога LLM оценивает, достигнута ли цель.

### C-03: Сводка угроз (`/threat summary`)
Еженедельная сводка актуальных угроз (APT, DDoS, ransomware, CVE) с анализом от учителя:
- Забирает свежие новости из RSS (SecurityWeek, CISA)
- Фильтрует по ключевым словам
- LLM составляет обзор, тренды и рекомендации
- Показывает источники

### C-04: APT досье (`/threats`, `/groups`)
7 готовых досье на APT-группы (APT28, APT29, Lazarus, APT41, Sandworm, FIN7, REvil) с:
- Алиасами, страной, активностью
- Тактиками MITRE ATT&CK
- Инструментами и техниками
- Ссылками на MITRE

`/groups` показывает группировку всех групп по странам и топ-10 тактик/инструментов.

### C-08: Песочница для кода (`/sandbox`)
Запуск пользовательского кода (Python, Bash) в изолированном Docker-контейнере:
- Валидация кода на опасные паттерны (встроенные функции, сетевые вызовы и т.д.)
- Ограничения: 256MB RAM, 0.5 CPU, нет сети, read-only FS, пользователь nobody
- Пример: `/sandbox python import sys; print(sys.version)`

### C-09: Адаптивный план обучения (`/adaptive`, `/quiz`, `/task`)
Система отслеживает слабые темы на основе успешности в квизах и заданиях:
- После каждого квиза/задания обновляется `success_rate` по теме
- При успешности <70% тема помечается как слабая
- При запуске `/quiz` фокус на слабой теме (если есть)
- Команда `/adaptive` показывает список слабых тем и рекомендации

### C-10: Интервальные повторения (`/repeat`)
Algoritmo SuperMemo (упрощённый SM-2) для интервальных повторений:
- После каждого квиза/задания планируется следующее повторение
- Интервалы: 1, 3, 7, 30 дней в зависимости от успешности
- При старте приложение напоминает о готовых повторениях
- Команда `/repeat` показывает темы, готовые к повторению, и запускает квиз

### C-11: Генерация конспектов (`/summary`)
Генерация структурированного конспекта по указанной теме с использованием RAG:
- RAG поиск по базе знаний по запросу
- Структура Markdown: введение, основные понятия, примеры, выводы
- Автоматическое сохранение в папку `summaries/`
- Пример: `/summary "SQL инъекции"`

### C-12: Автоматическая генерация writeup (`/auto_writeup`)
После завершения активности (квиз, задание, эпизод) автоматически создаётся структурированный отчёт:
- Сбор данных: вопросы, ответы, флаги, контекст
- RAG для дополнения примерами и ссылками
- Markdown-шаблон с анализом и рекомендациями
- Сохранение в `writeups/`
- Пример: `/auto_writeup`

### M-24: Команда `/help detail`
Подробная справка по каждой команде с примерами использования:
- Описание всех команд (режимы, обучение, практика, инструменты, отчёты, управление)
- Примеры ввода для каждой команды
- Доступна через `/help detail` или цифра 10 в меню
- Полезно для новых пользователей

### M-25: Интеграция HackTheBox (`/htb`)
Полноценная интеграция с HackTheBox для индивидуального обучения:
- **Авторизация**: `/htb login <email> <password>`
- **Список машин**: `/htb machines [all|free|pro]` — таблица машин с ID, ОС, сложностью, очками
- **Детали машины**: `/htb machine <id>` — описание, подсказки, рейтинг
- **Пошаговый разбор**: `/htb walkthrough <id>` — LLM генерирует детальный гайд по эксплуатации
- **Отправка флага**: `/htb submit <id> <flag>` — проверка и запись прогресса
- **Синхронизация**: `/htb sync` — получение активности с сервера
- **Статус**: `/htb status` — просмотр завершённых машин

Прогресс сохраняется локально и синхронизируется.

### M-26: Пошаговые разборы эксплойтов (`/walkthrough`, `/exploit`)
Система интерактивных гайдов по эксплуатации уязвимостей:
- **`/walkthrough <тема>`** — Генерация детального пошагового руководства по exploitation (SQLi, XSS, Buffer Overflow и т.д.)
  - Структура: введение, предварительные условия, шаги (разведка, сканирование, эксплуатация, пост-эксплуатация, защита)
  - Конкретные команды (nmap, gobuster, sqlmap, Burp)
  - Альтернативные варианты при ошибках
  - Советы по дебаггингу
  - Где тестировать (HTB, DVWA, TryHackMe)
- **`/exploit <CVE-ID>`** — Поиск готовых эксплойтов для CVE (через NVD, Exploit-DB ссылки)

Использует LLM для генерации, кэшируется 1 час.

### M-27: PoC Verification (`/exploit_submit`)
Для миссий, которые требуют реального exploitation, а не просто флага:
- **`/exploit_submit <mission_id> <step_order> <script_path>`** — отправить скрипт-эксплойт
  - Скрипт запускается в песочнице (Docker, ограничения: 256MB RAM, no network)
  - Валидация: проверка `stdout`/`stderr`/`exit_code` на ожидаемое значение (флаг)
  - Шаг миссии должен иметь `accepts_exploit: true` и `exploit_validation` в описании
  - При успехе шаг отмечается пройденным; afterwards `/mission submit` завершает миссию
- Замена флагов на PoC исключает читерство и учит писать рабочие эксплойты

Пример миссии (`missions/intro_web.json`):
```json
{
  "steps": [
    {
      "order": 1,
      "objective": "Найти SQL инъекцию...",
      "flag": "FLAG{...}",
      "accepts_exploit": true,
      "exploit_validation": {
        "type": "stdout_contains",
        "value": "FLAG{...}"
      }
    }
  ]
}
```

### M-28: Learner Dashboard (`/dashboard`)
Персональная аналитика в CLI:
- **Обзор**: Total XP, количество пройденных квизов, лабов, миссий, собранных флагов, заданий.
- **Слабые темы**: автоматически выводит темы с успешностью <70% (из `/adaptive`) с количеством попыток.
- **Прогресс по трекам**: кратко сколько тем завершено в каждом enrolled треке.
- **Активность**: счётчики сообщений, проверок новостей и т.п.
- Все данные обновляются в реальном времени из состояния приложения.

Пример: `/dashboard`

### M-29: Path-based Adaptive Learning Tracks (`/tracks`)
Структурированные учебные траектории для последовательного обучения:
- **Треки** — YAML-файлы в папке `tracks/` определяют последовательность тем, prerequisites, лаборатории, квизы.
- **Команды:**
  - `/tracks list` — показать все доступные треки
  - `/tracks start <id>` — записаться на трек
  - `/tracks next` — получить следующую тему в текущем треке
  - `/tracks progress [id]` — показать прогресс (пройдено/всего)
  - `/tracks complete <topic_id>` — отметить тему пройденной (после квиза или вручную)
  - `/tracks recommend` — персональные рекомендации на основе слабых тем (`/adaptive`)
  - `/tracks status` — текущий активный трек
  - `/tracks reset [id]` — сбросить прогресс
- **Адаптивность:** треки могут быть адаптивными (`adaptive: true`), тогда система учитывает `weak_topics` и предлагает треки, покрывающие слабые области.
- **Прогресс:** сохраняется в `state.tracks_enrolled` и `state.track_progress`. При завершении трека начисляется бонус XP (50 очков * часов).
- **Примеры треков** (готовые):
  - `web-fundamentals` — основы веб-уязвимостей (SQLi, XSS, CSRF) для новичков
  - `network-security` — сетевая разведка и эксплуатация (nmap, SMB, FTP, SSH)
  - `privesc-master` — повышение привилегий в Linux/Windows
  - `ctf-prep` — подготовка к CTF (веб, стеганография, крипто, forensic)

Треки интегрированы в цифровое меню (цифра **20**) и в `/help`.

### M-30: Real-time Hints (`/hint`)
Контекстные подсказки во время выполнения заданий:
- **Автоматические подсказки** — система анализирует ввод (nmap, sqlmap, curl) и показывает релевантные советы
- **Команды управления:**
  - `/hint on|off` — включить/выключить автоматические подсказки
  - `/hints` — статистика использованных подсказок
  - `/hint get` — получить ручную подсказку (тратит кредит)
  - `/hint clear` — сбросить счётчики
- **Механика:**
  - 3 кредита на сессию (новые пользователи)
  - Каждая подсказка снижает XP на 10% (автоматические) или 5% (ручные)
  - Кулдаун 30 секунд между автоматическими
  - Сбрасывается при запуске миссии/лаборатории
 - **Конфигурация паттернов:** `hints/patterns.json` — можно добавлять свои regex и советы
 - **Цель:** помогать, когда застрял, но поощрять самостоятельное мышление через лимиты и штрафы

### M-31: Bug Bounty Simulation (`/bounty`)
Интерактивная симуляция хаунтинг-отчётов:
- **Цель:** написать профессиональный отчёт об уязвимости для разработчиков.
- **Сценарий:** система случайно выбирает тип уязвимости (SQLi, XSS, CSRF, File Upload, IDOR) и описание тестового веб-приложения.
- **Интерактивность:** бот задаёт структурированные вопросы:
  - Краткий заголовок
  - Тип уязвимости (можно изменить)
  - Краткое описание (что, где, как)
  - Шаги воспроизведения (пошагово)
  - Возможный ущерб (impact)
  - Рекомендуемое исправление
- **LLM-ревью:** после отправки LLM выступает в роли триage-эксперта и оценивает отчёт:
  - **Критерии:** полнота, ясность, техническая точность, воспроизводимость.
  - **Результат:** JSON со `score` (0-100), `feedback`, `strengths`, `improvements`, `badges`.
- **Награда:** XP = 50 + `score`*2. Чем лучше отчёт, тем больше XP.
- **История:** все отчёты сохраняются в `state.bounty_reports`, можно просматривать позже.
- **Цель обучения:** научиться оформлять баг-репорты, понимать структуру качественного описания уязвимости, получать конструктивную обратную связь.

Пример: `/bounty`

```
╔══════════════════════════════════════╗
║  Bug Bounty Simulation              ║
║  Вы — white-hat хакер...            ║
╚══════════════════════════════════════╝
Цель: SQL Injection in Login Form
Контекст: PHP+MySQL, ошибки скрыты.
...
```

Все данные сохраняются в состоянии приложения.

## 🔧 Настройка

### Переключение провайдера LLM
```python
# В config.py
LLM_PROVIDER = "ollama"   # локально
# или
LLM_PROVIDER = "openrouter"  # облако
```

Для **OpenRouter**:
1. Получите ключ на https://openrouter.ai/keys
2. Установите: `export OPENROUTER_API_KEY=sk-...`
3. Выберите модель: `OPENROUTER_MODEL = "mistralai/mixtral-8x7b-instruct"`
