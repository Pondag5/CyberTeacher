# ADR-005: Rate limiting с помощью sliding window

## Статус
Принято

## Контекст
Необходимо ограничивать частоту запросов пользователя к боту (10 запросов в минуту) для предотвращения злоупотреблений и снижения нагрузки на LLM.

## Решение
В `state.py` добавлен список `request_timestamps`. Перед каждым пользовательским вводом вызывается `can_make_request()`:
- Очищает список от устаревших меток (старше 60 секунд).
- Разрешает, если текущее количество меток < 10.
При разрешении `record_request()` добавляет текущую метку времени.

Такой подход реализует sliding window без необходимости фоновых задач.

## Последствия
- Простота реализации и отсутствие зависимостей.
- Ограничение на уровне CLI (не защищает от прямого вызова API, но CLI — единственный интерфейс).
- Метки сохраняются между перезапусками (в app_state.json), что может привести к начальному禁止, если файл старый — но это не страшно.
