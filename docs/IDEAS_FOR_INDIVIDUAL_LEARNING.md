# Идеи для CyberTeacher (фокус на индивидуального ученика)

## 📋 Список идей (15 шт.)

### 1. PoC Verification вместо флагов (M-27)
**Проблема:** Сейчас можно просто скопировать флаг из walkthrough. Нет проверки, что ученик действительно эксплуатировал уязвимость.

**Решение:** 
- Заменить флаги на **приём PoC (Proof of Concept) кода**
- Команда `/exploit_submit <mission_id> <exploit_script.py>`
- Система запускает скрипт в песочнице и проверяет результат (флаг в выводе, файл, изменение БД)
- Автоматическая оценка: `exploit_ok`, `timing`, `reliability`
- XP выдаётся только если эксплойт рабочий

**Затрагивает:** missions/, practice/, handlers/quiz.py (оценка), sandbox enhancements

**Приоритет:** Высокий (исключает читерство, учит реальному exploitation)

### 2. Path-based Adaptive Learning Tracks (M-29)
**Проблема:** `/adaptive` показывает слабые темы, но нет последовательного плана обучения.

**Решение:**
- Ввести **обучающие треки (tracks)**:
  - "Web Security 101": 10 шагов (SQLi → XSS → CSRF → File Inclusion → RCE)
  - "Network Pentest": сканирование → MITM → pivoting → post-exploit
  - "Malware Analysis": static → dynamic → unpacking → C2
- После каждого квиза система рекомендует: "Ты ошибся в XSS → повтори тему X или перейди к Y"
- Возможность пропустить тему, если сдал квиз с ≥90%
- Прогресс по треку отображается в отдельной команде `/track`

**Реализация:**
- `tracks/` папка с YAML-описанием (шаги, критерии, связанные миссии)
- `track_engine.py` — движок, который управляет прогрессом
- Интеграция с `weak_topics` для адаптации

**Приоритет:** Высокий (даёт структуру, виден прогресс)

### 3. Real-time Hints & Co-pilot (M-30)
**Проблема:** Ученик может застрять на лаборатории без подсказок. Сейчас только `hint` в миссии и `trace_hint` по таймеру.

**Решение:**
- **Контекстные подсказки в реальном времени**:
  - Если ввод содержит `' OR '1'='1` в DVWA → "Попробуй добавить ` UNION SELECT`"
  - Если много неудачных попыток (nmap, gobuster) → LLM генерирует подсказку на основе последних действий
  - `/hint` в любое время (даже без таймера) — но лимит на подсказки
- **Лимит:** 3 подсказки за лабу, каждая снижает XP на 10%
- Подсказки логируются в `memory/trace.log`

**Реализация:**
- Мониторинг `input()` в `main.py` (перехват)
- Анализ команд (nmap, sqlmap, Burp) на паттерны
- Кэширование подсказок (чтобы не повторялись)

**Приоритет:** Высокий (уменьшает фрустрацию, помогает учиться)

### 4. Learner Dashboard (личная аналитика) (M-28)
**Проблема:** `/stats` показывает только очки/флаги. Нет глубокой аналитики.

**Решение:**
- **Графики:**
  - success_rate по темам over time (Matplotlib/ASCII-графики)
  - Heatmap активности (когда в какое время учишься)
  - Количество запущенных лабораций по категориям
- **Предсказания:**
  - "Риск забросить": если нет активности 7 дней → уведомление
  - "Оптимальное время повторения": на основе SM-2
- **Рекомендации от LLM:** "Сфокусируйся на SQLi (success_rate 50%), повтори через 3 дня"
- Новая команда `/analytics` — интерактивный режим просмотра графиков

**Реализация:**
- Использовать существующие метрики (Q-04: LLM instrumentation, cache stats)
- Matplotlib для PNG-графиков (сохранять в `reports/`),ASCII для CLI
- Интеграция с `state.weak_topics` и `review_schedule`

**Приоритет:** Высокий (мотивация через визуализацию)

### 5. Bug Bounty Simulation (M-31)
**Проблема:** Нет имитации реального bug bounty цикла (отчёты, ребаунды, ревью).

**Решение:**
- Режим "Bug Bounty":
  1. Специальная лаборатория "BuggyCorp v1.0" (или статический сайт в `sandbox/`)
  2. Ученик находит уязвимость, пишет **отчёт** по шаблону (CVE, описание, PoC, impact)
  3. Система (LLM) выступает как **ревьюер**:
     - Принимает или отклоняет
     - Может попросить "ребаунд": "Уточни, как именно exploitable? Добавь PoC"
  4. При принятии — награда (виртуальные деньги, звания, XP)
  5. Можно повторять: сложность растёт, отчёты становятся строже

**Шаблон отчёта (Markdown):**
```markdown
## Vulnerability Report
- **Product**: BuggyCorp v1.0
- **CVE**: (опционально)
- **Type**: SQL Injection
- **Description**: ...
- **Steps to Reproduce**:
  1. ...
  2. ...
- **PoC**: (код/curl)
- **Impact**: Confidentiality loss, etc.
```

**Реализация:**
- Команда `/bounty submit <report.md>`
- LLM промпт для ревью (с criteria checklist)
- История отчётов в `memory/bounty_reports.json`

**Приоритет:** Средний/Высокий (очень практично для карьеры)

### 6. Voice Assistant (TTS/STT) (M-34)
**Проблема:** Учиться только с клавиатуры. Хочется повторять квизы в метро/машине.

**Решение:**
- **TTS (Text-to-Speech):** `/speak on` — бот читает вопросы/ответы голосом
  - Использовать Silero TTS (русский) или Coqui TTS
  - Регулировка скорости
- **STT (Speech-to-Text):** `/listen` — голосовой ввод вместо `input()`
  - Vosk (офлайн) или Whisper (онлайн)
- **Голосовые подсказки:** случайные факты о безопасности while walking

**Реализация:**
- Зависимости: `silero-tts`, `vosk` (или `openai-whisper`)
-Background thread для прослушивания микрофона
- **Важно:** индикатор "слушаю..." в UI

**Приоритет:** Низкий/Средний (фича для удобства, не критично)

### 7. Local Exploit Database
**Проблема:** `/exploit` ищет только по CVE (через NVD). Нет локального хранилища эксплойтов.

**Решение:**
- **Автоматический парсинг:**
  - Exploit-DB (через API или GitHub mirror)
  - GitHub trending (поиск по `exploit`, `0day`, `CVE`)
  - Сбор метаданных: CVE, теги (web, network, dos), автор, дата
- **Локальная база:** `exploits/` (SQLite или JSON) с индексацией
- **Поиск по тегу:** `/exploit web` → все веб-эксплойты
- **Связь с walkthrough:** если есть готовый эксплойт в базе, walkthrough показывает ссылку "実装例"

**Реализация:**
- `exploit_db/` парсер (раз в день обновляет)
- RAG-подобный поиск по описанию
- `/exploit search <keyword>`

**Приоритет:** Средний (ускоряет поиск, но не критично)

### 8. Adaptive Weak Topic Quizzing
**Проблема:** `/adaptive` показывает слабые темы, но не предлагает немедленно их прокачать.

**Решение:**
- Новая команда `/test_weak`:
  - Берёт топ-3 слабые темы из `weak_topics`
  - Генерирует по 2-3 вопроса на каждую (всего 6-9)
  - Запускает мини-квиз
- После квиза автоматически обновляет `weak_topics`
- Если success_rate становится >70% — удаляет тему из слабых

**Реализация:**
- Расширение `question_generation.py` — функция `generate_weak_topic_questions(topic)`
- Ограничение: не спрашивать темы, которые уже были в последнем обычном `/quiz`

**Приоритет:** Высокий (помогает целенаправленно улучшаться)

### 9. Custom Assignment Generation (M-24 upgrade)
**Проблема:** `/genassignment` — stub. Нет реальной генерации.

**Решение:**
- На основе **слабых тем** (`/adaptive`) генерировать **кастомное задание**:
  - `/genassignment` → показывает 3 темы для выбора
  - После выбора: "Найди SQLi на этом сайте: [URL]"
  - Проверка через sandbox (отправка PoC-скрипта)
  - Автоматическая оценка: `exploit_ok` + качество кода
- Шаблоны заданий в `assignment_templates/`:
  - `web_discovery.yaml`: "Найди endpoint /admin"
  - `sqli_extract.yaml`: "Извлеки данные из БД через UNION"
  - `xss_payload.yaml`: "Докажи XSS через `<script>alert(1)</script>`"
- Интеграция с `/walkthrough`: можно запросить разбор, если не получается

**Реализация:**
- `assignment_generator.py` — использует LLM + templates
- Sandbox для тестирования PoC (запуск скрипта в ограниченной среде)

**Приоритет:** Высокий (закрывает цикл "слабая тема → задание → проверка")

### 10. HTB Walkthrough Contextual
**Проблема:** Walkthrough для HTB генерируется без учёта, проходил ли пользователь машину.

**Решение:**
- Если `machine_id` в `state.htb_completed` → "разбор" в режиме **"как было решено"** (возможны альтернативные пути)
- Если нет → "подсказки без полного решения" (постепенное раскрытие):
  - Шаг 1: общая идея (enumeration)
  - Шаг 2: векторы атаки (начни с nmap)
  - Шаг 3: конкретная уязвимость (если пользователь застрял >10 мин)
- Интеграция с `/adaptive`: если пользователь **постоянно тупит на машинах определённого типа** (например, Windows), recommending focused track

**Реализация:**
- В `handle_htb_walkthrough` проверять `machine_id` in `htb_completed`
- Разные промпты для "fresh" и "completed"
- Время сессии + trace_hint помогали бы в логике раскрытия

**Приоритет:** Средний

### 11. Competitive Element (без multi-user)
**Проблема:** Нет соревновательного мотиватора. Только собственные рекорды.

**Решение:**
- **Личные рекорды:**
  - "Самая быстрая машина" (время от login до root)
  - "Наибольшее число флагов за день" (ежедневный рекорд)
  - "Самая длинная серия" (дней подряд с активностью)
- **Челленджи (генерируются автоматически):**
  - Ежедневные: "Пройди 1 машину среднего уровня"
  - Ежедневные: "Соверши 10 подсказок" (да, специально)
  - Еженедельные: "За 7 дней собери 3 флага"
- **Сравнение с прошлым собой:** "Ты улучшился на 15% за неделю (success_rate)"

**Реализация:**
- Хранить рекорды в `state.personal_best`
- При старте приложения показывать "Твой рекорд: X флагов за день"
- История рекордов в `memory/records.json`

**Приоритет:** Низкий/Средний (мотивация через game mechanics)

### 12. "Exam Mode" (режим экзамена)
**Проблема:** Нет симуляции стрессовой среды (таймер, ограничения).

**Решение:**
- Команда `/exam start <course_id>`:
  - Случайный набор из 10 вопросов по курсу
  - Таймер: 60 минут
  - Нельзя использовать подсказки (`/hint` заблокирован)
  - Нельзя листать вперед/назад (последовательные вопросы)
- По завершении:
  - Оценка: A (90-100), B (80-89), C (70-79), F (<70)
  - Генерация **сертификата** (Markdown-файл в `certificates/`)
  - Запись в `state.exams` с датой, числом вопросов, оценкой
- Можно повторять: вопросы меняются (извлечение из темы + raг)

**Реализация:**
- `exam_engine.py`
- Таймер в main loop (если mode == EXAM)
- Шаблон сертификата

**Приоритет:** Низкий

### 13. TryHackMe Integration ( sibling to HTB)
**Проблема:** HTB — одна платформа. THM имеет структурированные пути (rooms, paths).

**Решение:**
- Аналогичный `/thm` модуль:
  - `/thm login` (API token)
  - `/thm rooms` (список комнат)
  - `/thm start <room>` (запуск комнаты, если есть Docker-образ или URL)
  - `/thm progress` (синхронизация)
- **Отличие от HTB:** THM больше учебный, есть ready-made labs
- Можно импортировать已完成 как миссии в CyberTeacher

**Приоритет:** Средний (расширяет охват)

### 14. Universal Smart Search
**Проблема:** RAG работает, но интерфейс — только `/read_url`. Нет универсального поиска по всей пирамиде знаний.

**Решение:**
- Команда `/search <query>` — полнотекстовый поиск по:
  - База знаний (PDF)
  - Новости (кэшированные и свежие)
  - CVE база
  - Собственные writeups
  - Документация проекта (README, ADRs)
- **Фильтры:**
  - `/search web` (только веб-темы)
  - `/search 2024` (только 2024 год)
  - `/search -apt` (исключить APT)
- **Сохранение результатов:** в `writeups/search_results/` как Markdown

**Реализация:**
- `universal_search.py` — объединяет все индексы (FAISS + SQLite full-text)
- Адресация: `source: knowledge_base`, `source: cve`, `source: news`

**Приоритет:** Средний

### 15. Auto Progress Summary (еженедельный отчёт)
**Проблема:** Нет автоматического рефлексирования прогресса.

**Решение:**
- При старте приложения (или по команде `/summary_progress`):
  - Если прошло ≥7 дней с последнего summary
  - LLM анализирует:
    - Какие темы прошёл за неделю
    - Какие слабые (success_rate <70%)
    - Сколько времени потратил (логи)
    - Какие миссии завершил
  - Генерирует **недельный отчёт**:
    - "Ты прокачал SQLi, но XSS всё ещё слаб"
    - "Рекомендую: реши 3 задачи по XSS, затем повтори через 5 дней"
    - Графики ASCII (активность по дням)
  - Отчёт сохраняется в `reports/weekly_YYYY-MM-DD.md` и выводится в чат

**Приторитет:** Низкий (но полезно для дисциплины)

## 🎯 Рекомендуемый порядок реализации для индивидуального ученика:

1. **M-27 PoC verification** — сразу после HTB submit (замена флагов на скрипты)
2. **M-29 Tracks** — даёт структуру обучению
3. **M-30 Real-time hints** — улучшает опыт на labs
4. **M-28 Learner dashboard** — визуализация прогресса
5. **M-31 Bug bounty** — практика реальных сценариев
6. **Custom assignments** (из этой liste) — закрывает цикл адаптации
7. Остальное — по мере времени
