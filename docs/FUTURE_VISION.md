# Будущее развитие CyberTeacher

Этап H-01..H-10 завершён. Ниже — 10 ключевых направлений для превращения проекта в полноценную образовательную платформу.

---

## 1. Step-by-Step Exploit Walkthroughs
**Проблема:** Сейчас ученик получает флаг и XP, но не видит пошагового разбора, *почему* уязвимость работает.  
**Решение:** После успешного прохождения миссии/лаборатории предлагать интерактивный "разбор полётов":
- Показать исходный уязвимый код (например, DVWA SQLi)
- Пошагово показать, как меняется запрос (`' OR '1'='1`), как выглядит SQL-запрос на стороне сервера
- Визуализировать вывод БД (например, через `sqlite3` или `mysql` CLI)
- Объяснить root cause (неподготовленный запрос, экранирование)
- Дать рекомендации по fix (prepared statements, WAF)
**Реализация:** Добавить `walkthroughs/` папку с JSON-шаблонами, команду `/walkthrough <mission_id>`.

## 2. Exploit Submission & Verification
**Проблема:** Сейчас флаг можно просто скопировать. Нет проверки, что ученик действительно эксплуатировал уязвимость.  
**Решение:** Заменить флаги на **приём PoC (Proof of Concept) кода**:
- Ученик отправляет скрипт (Python/Bash) через `/exploit <mission_id>`
- Система запускает его в песочнице (изолированно) и проверяет результат (флаг в выводе, файл, изменение БД)
- Автоматическая оценка: `exploit_ok`, `timing`, `noise`
**Реализация:** Новый обработчик `handle_exploit()`, расширение миссий полем `"accepts_exploit": true`, sandbox enhancements.

## 3. HackTheBox / TryHackMe Integration
**Проблема:** Локальные лаборатории (DVWA, Juice Shop) — это только первые шаги. Нужны реальные машины.  
**Решение:** Интеграция с HTB/THM API:
- Команда `/htb machines [type]` — список доступных машин (сложность, тип)
- Автоматическое создание миссий на основе HTB задачи (спаWN машины, мониторинг результата)
- Синхронизация прогресса: завершённые машины отмечаются в `state.htb_completed`
**Реализация:** Вызов HTB API, сохранение токена в конфиге, парсинг заданий, импорт как миссий.

## 4. Multi-User & Leaderboard
**Проблема:** Нет социальной мотивации. Ученик один, нет соревновательного элемента.  
**Решение:** Добавить систему пользователей (локальная SQLite):
- Регистрация/авторизация (`/login`, `/register`, `/logout`)
- Таблица лидеров: `/ranking` (XP, пройдено миссий, слабые темы)
- Командный режим: `/team create <name>`, совместные миссии
- API token для веб-интерфейса
**Реализация:** Новые таблицы в БД (`users`, `teams`, `team_members`), middleware в `main.py` (сессии), защита команд.

## 5. Instructor Dashboard
**Проблема:** Преподаватель не видит прогресс класса, не может создать custom assignments.  
**Решение:** Веб-интерфейс для инструктора:
- Просмотр всех учеников (XP, слабые темы, активность)
- Создание миссий через UI (форма JSON) или загрузка из файла
- Назначение домашних заданий, дедлайны
- Экспорт статистики (CSV) для отчётов
**Реализация:** Расширение `web_ui.py` с новой вкладкой "Instructor", новые эндпоинты FastAPI/Streamlit, проверка роли.

## 6. Path-Based Adaptive Learning
**Проблема:** Сейчас `adaptive` показывает слабые темы, но не предлагает конкретный маршрут.  
**Решение:** Ввести **обучающие треки (tracks)**:
- "Web Security 101": 10 шагов (SQLi→XSS→CSRF...)
- "Network Pentest": сканирование,MITM, pivoting
- После каждого квиза система рекомендует: "Ты ошибся в XSS → повтори тему X или перейди к Y"
- Возможность пропустить тему, если сдал квиз с 90%
**Реализация:** `tracks/` папка с YAML-описанием, движок `PathEngine`, интеграция с `weak_topics`.

## 7. Real-Time Hints & Co-pilot
**Проблема:** Ученик может застрять на лаборатории без подсказок. Сейчас только `hint` в миссии и `trace_hint` по таймеру.  
**Решение:** Добавить **контекстные подсказки в реальном времени**:
- Если ученик ввёл что-то похожее на `' OR '1'='1` в DVWA — показать "Попробуй добавить ` UNION SELECT`"
- Если много неудачных попыток — LLM генерирует подсказку на основе последних действий
- Подсказки потребляют "кредиты" или снижают XP за прохождение
**Реализация:** Мониторинг input в `main.py`, вызов `LLM.generate_hint(context)` при запросе `/hint`, лимит на подсказки.

## 8. Bug Bounty Simulation
**Проблема:** Нет имитации реального bug bounty цикла (отчёты, ребаунды, реwasser).  
**Решение:** Создать режим "Bug Bounty":
- Ученик находит уязвимость на "тестовом" сайте (специальная лаборатория)
- Пишет отчёт по шаблону (CVE, описание, PoC, impact)
- Система оценивает отчёт (LLM как рецензент) и выдаёт награду (виртуальные деньги)
- Возможны "ребаунды": LLM просит уточнить детали, дополнить PoC
**Реализация:** Команда `/bounty submit`, шаблон отчёта (Markdown), LLM-рецензирование, история отчётов.

## 9. Mobile Companion App (PWA)
**Проблема:** Н练习 только на ПК. Хочется повторять квизы в метро.  
**Решение:** Создать **Progressive Web App**:
- Интерфейс на React/Flutter Web, кэширование для офлайна
- Основные функции: квизы, просмотр прогресса, уведомления о напоминаниях
- Синхронизация через Firebase/custom API
**Реализация:** Отдельный `frontend/` папка, REST API в `main.py` (FastAPI), auth tokens.

## 10. Advanced Analytics & AI Tutor
**Проблема:** Учитель — это LLM, но нет аналитики по эффективности обучения.  
**Решение:**
- **Персональная аналитика:** Графики прогресса по темам (success_rate over time), heatmap активности
- **AI-рекомендации:** На основе данных (ошибки, время) LLM предлагает: "Сфокусируйся на X", "Повтори Y через 3 дня"
- **Predictive modeling:** Предсказать, когда ученик забросит, и отправить мотивационное сообщение
**Реализация:** Новые команды `/analytics`, `/ai_recommendations`; интеграция с метриками (Q-04), ML lightweight (scikit-learn) или LLM prompts.

**Заключение:** Проект уже полноценный MVP. Чтобы выйти на уровень платформы, нужно:
1. Углубить **обучающий контент** (walkthroughs, bug bounty)
2. Добавить **социальный слой** (multi-user, leaderboard)
3. Сделать **адаптивность умнее** (tracks, real-time hints)
4. Интегрировать **внешние платформы** (HTB)
5. Расширить **аналитику** и **инструкторские инструменты**

Пользователь может начать с любого из этих направлений в зависимости от спроса.
