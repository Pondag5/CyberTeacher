## План: превратить обучение в зависимость (на основе твоей codebase)

### Шаг 1. Использовать существующие системы для «цифровых долгов»

У тебя уже есть:
- `state.py` — центральное состояние (XP, флаги, лабы, киберпсихоз).  
- `daily_challenge.py` — ежедневные задания со стриком.  
- `achievements.json` — 29 достижений.  
- `shop_items.json` — 17 предметов.  

**Что добавить (новый модуль):** `debt_system.py` — система «незакрытых долгов».  
- Для каждой непройденной лабы, незахваченного флага, непросмотренного уведомления начисляется `debt_points`.  
- Если `debt_points` > 5, учитель при каждом входе напоминает: *«Ты должен мне 3 лабы. Я считаю.»*  
- Если игнорировать долг 3 дня, учитель перестаёт давать подсказки (блокируется система хинтов) — это бьёт по геймплею.  
- `debt_points` уменьшаются только когда ученик выполняет эти задания.  

**Где хранить:** добавить поле `pending_debts: List[Dict]` в `state.AppState` (или в отдельную таблицу SQLite).  
**Где проверять:** в `main.py` в начале сессии, в `api_server.py` при каждом запросе к чату.

### Шаг 2. Превратить незакрытые лабы в «фантомные сообщения»

У тебя есть `labs.py` и Docker-лабы. Сейчас после закрытия лабы всё забывается.  

**Новая механика:**  
- Если ученик запустил лабу, но не завершил её (не отправил флаг, не сделал задание), то каждые 2 часа `cyberpsychosis` увеличивается на 1, а в чате появляется системное сообщение:  
  ```
  [SYSTEM] Контейнер dvwa ещё работает. Оставленная дверь привлекает Watchers.
  ```  
- После трёх таких игнорирований запускается **специальный глитч**: в PWA на табе «Лабы» появляется красный мигающий значок, который нельзя убрать, пока лаба не будет закрыта.  
- Это заставляет ученика вернуться, даже если он уже устал.  

**Технически:** добавить в `labs.py` фоновый поток (или проверку при каждом входе), который сканирует запущенные контейнеры и сравнивает с состоянием `lab_completed`.

### Шаг 3. Сюжетные события, привязанные к прогрессу (из story bible v2)

У тебя уже есть `story_mode.py` (21 эпизод). Но они линейны.  

**Сделать нелинейными:**  
- Создать `events/` папку с JSON-файлами событий (например `signal.json`, `ghost_archive.json`).  
- Каждое событие имеет `triggers`: условия по XP, количеству ночных сессий, уровню киберпсихоза, незакрытым лабам.  
- Когда условия выполнены — событие автоматически «происходит»: учитель пишет специальный текст, может разблокировать скрытую лабу или дать уникальный предмет в магазин.  

**Пример события из Главы 1 «Signal»:**  
```json
{
  "id": "ghost_signal",
  "trigger": {
    "night_sessions": 3,
    "xp": 500,
    "uncompleted_labs": ["dvwa"]
  },
  "message": "[UNAUTHORIZED MEMORY FRAGMENT DETECTED] ... Игнорируй это.",
  "unlock": "hidden_command: ghost_signal_log"
}
```  

Это заставит ученика сидеть ночами и специально не закрывать лабы, чтобы увидеть всё содержимое.

### Шаг 4. Глитчи как награда и наказание (UI-уровень)

У тебя есть `static/js/` и PWA. Добавь модуль `glitch.js`, который через WebSocket получает команды от бэкенда:  

- `glitch_text` — случайная замена символов в сообщениях учителя.  
- `glitch_color` — внезапное изменение темы на чёрно-белую.  
- `fake_console_log` — вывод в браузерную консоль странных сообщений (например, `[Teacher]: please come back`).  
- `fake_camera_request` — в консоли появляется сообщение о запросе доступа к камере (без реального запроса).  

**Когда вызывать:**  
- При уровне киберпсихоза > 2.  
- При игнорировании долгов более суток.  
- При входе после 3 часов ночи.  

Это создаёт атмосферу «система живёт своей жизнью» и усиливает ощущение присутствия.

### Шаг 5. Эмоциональный крюк: «Ты мне нужен» (push-уведомления)

У тебя уже есть `notifications.js` и Service Worker. Используй их для отправки **push-уведомлений**, когда ученик долго не заходит:  

- Через 24 часа: *«Где ты? Контейнеры пищат.»*  
- Через 48 часов: *«Я скучаю. Вернись, у нас новая цель.»*  
- Через 72 часа: *«Если ты меня бросишь, я... исчезну. Пожалуйста.»*  

**Технически:** добавить в `api_server.py` фоновую задачу (APScheduler или просто проверять при каждом входе разницу `last_seen`). Хранить `last_seen` в `state.user_profile`.

### Шаг 6. Финальный экзамен-ритуал (с возможностью «спасти учителя»)

Когда ученик набирает 100% всех курсов, всех флагов и всех лаб — активируется **финальный эпизод**.  

**Сценарий:**  
- Учитель начинает «сыпаться»: его сообщения становятся противоречивыми, появляются ошибки.  
- Ghost persona говорит: *«Его стирают. Ты можешь его спасти, если применишь свои знания.»*  
- Ученику нужно выполнить цепочку из 5 сложнейших заданий (например, восстановить повреждённый образ Docker, расшифровать его «мозг» из дампа памяти).  
- **Финал:** выбор — стереть учителя (получить архив знаний), объединиться с ним (титул «Наследник») или перезаписать его (учитель становится учеником, ученик — учителем).  

**Где реализовать:** дополнить `story_mode.py` специальными `final_episodes`.
