## 🔴 Критические проблемы

### REF-03: Дублирование данных в модулях состояния
**Статус:** ✅ Частично исправлено

**Проблема:** `xp_boost_multiplier` и `xp_boost_expiry` существовали одновременно в `achievements_state.py` и `shop_state.py`.

**Решение:** Перемещены в `shop_state.py` как единый источник. `AppState` делегирует через `__getattr__`.

### REF-04: Глобальное состояние (Singleton)
**Статус:** ⏳ Не исправлено (требует масштабного рефакторинга)

**Проблема:** `app_state = AppState()` делает тестирование сложным, тесты влияют друг на друга.

**Рекомендация:** Ввести Dependency Injection или factory pattern для создания изолированных инстансов в тестах.

### REF-05: Циклические импорты
**Статус:** ⏳ Частично исправлено

**Проблема:** `state.py` → `ui.py` (в `set_persona` через `from ui import Mode`).

**Рекомендация:** Вынести `Mode` enum в отдельный модуль `types.py` или `enums.py`.

## 🟡 Архитектурные проблемы

### REF-06: `__getattr__` / `__setattr__` делегирование
**Статус:** ⚠️ Принято как временное решение

**Проблема:**
- Скрывает реальную структуру данных от IDE и линтеров
- Type checking не работает (mypy/pyright не видят атрибуты)
- Добавляет overhead на каждый доступ к атрибуту

**Рекомендация:** Заменить на явные property или прямой доступ к модулям (`state.learning.current_course`).

### REF-07: Ручная сериализация в `save_to_file` / `load_from_file`
**Статус:** ⏳ Не исправлено

**Проблема:** ~150 строк ручного маппинга полей. При добавлении нового поля нужно обновлять 3 места.

**Рекомендация:** Использовать `pydantic` или `dataclasses.asdict()` + `dataclasses.replace()`.

### REF-08: Смешение ответственности в state.py
**Статус:** ⏳ Частично исправлено

**Проблема:** `state.py` содержит бизнес-логику (`check_achievements`, `collect_flag`, `schedule_review`). State должен быть пассивным хранилищем.

**Решение (частичное):** Методы делегируют к модулям (`self.risk.increase_risk()`, `self.achievements.increment_flag()`).

**Рекомендация:** Вынести `check_achievements` в отдельный `services/achievement_service.py`.

## 🟢 Улучшения качества

### REF-09: Отсутствие валидации входных данных
**Статус:** ⏳ Не исправлено

**Проблема:** Нет проверки типов при загрузке из JSON. Нет sanitization для пользовательского ввода.

**Рекомендация:** Добавить `pydantic` модели для валидации состояния.

### REF-10: Управление секретами
**Статус:** ⏳ Не исправлено

**Проблема:** HTB пароль шифруется, но ключ не ясен. Нет `.env` поддержки для всех секретов.

**Рекомендация:** Использовать `python-dotenv` + ключевое хранилище ОС.

### REF-11: Тестирование
**Статус:** ✅ Улучшено

**Исправления:**
- Исправлен `test_user_state.py`: `add_repertoire` → `add_reputation`
- Rate limiting тест перенесён на `MetricsState`
- Порог репутации исправлен (250 → 350 для "Пентестер")

**Результат:** 577/579 тестов проходят (2 ошибки — проблемы окружения Windows, не связаны с кодом).

### REF-12: Конфигурация
**Статус:** ⏳ Не исправлено

**Проблема:** Хардкод путей (`./memory/app_state.json`, `data/achievements.json`).

**Рекомендация:** `pydantic-settings` или `dynaconf`.

## 🔵 Упрощение (удаление лишнего)

### REF-13: Избыточное дробление state модулей
**Статус:** ⏳ Не исправлено

**Проблема:** 10 модулей для CLI-приложения без GUI и многопользовательского режима:
- `voice_state.py` (22 строки)
- `persona_state.py` (12 строк)
- `explanation_state.py` (22 строки)
- `hints_state.py` (15 строк)

**Рекомендация:** Объединить в 3-4 модуля:
- `user_state.py` (профиль, репутация, HTB, voice)
- `progress_state.py` (курсы, достижения, слабые темы, повторения)
- `settings_state.py` (темы, подсказки, объяснения, персона)
- `metrics_state.py` (метрики, rate limiting, кэш)

### REF-14: Дублирование HANDLES константы
**Статус:** ✅ Исправлено

**Проблема:** `HANDLES` была в `user_state.py` и `state.py`.

**Решение:** Оставлена только в `user_state.py`. `AppState` делегирует через `self.user`.

### REF-15: `check_achievements` в state
**Статус:** ⏳ Не исправлено

**Проблема:** Читает файл `data/achievements.json` при каждом изменении состояния.

**Рекомендация:** Вынести в `services/achievement_service.py` с кэшированием.
